Бот ловит механику, а не ощущение: ошибки страницы, утечки текста (`undefined`, `{x}`, `NaN`), обрезку и выход за край, перекрытые кнопки, мёртвые часы, застрявший пролог, частоту модалок, «нечего делать». Ощущение — по скриншотам и журналу в отчёте.

1. Сборка свежая: `cd work && py -3 ../tools/build.py` (или `bash tools/regress.sh smoke`).
2. Прогон (из корня):
   - `node tools/playtest.js --minutes 3` — чистое время игрока, ~700–900 лет на ×10.
   - `node tools/playtest.js --minutes 3 --god` — на god-сборке (`node tools/make-god.js` перед этим): пустые отрезки промотаны, доходит до Ночи и ковчега. В отчёте помечено — это не темп игрока.
   - `--viewport 390x844` — телефон; `--seed N`; `--shots` — скриншот каждые 300 лет.
   - `--brain sim --style rush|serial|ark|bank` — решения принимает голова бота ядра (`tools/sim.js` step()) через API ядра в странице, не кликами; интерфейс рисуется, модалки и аудит работают. Так бот доходит до Ночи и ковчега за `--god --minutes 14`; в отчёте — души и уровень ковчега. Для проверки кликов используй UI-политики без `--brain`.
   - `--style serial` — «постепенный» (один мир за раз, разведка когда заселять нечего, ковчег вкладами ур. 2); `--style rush` — «рашер» (всё сразу, по два курьера на мир, вабанк). Папка отчёта получает суффикс `-<стиль>` и `-god`. Чтобы дойти до Ночи и ковчега, рашеру нужно `--god --minutes 12`: он занят каждый год, промотки не срабатывают.
3. Результат: `work/playtest/<метка>/report.md` + `events.json` + `game-log.json` (для агента `balance`) + `shots/`. Код выхода 1 = есть crit.
4. Разбор: каждую строку «Найденное» перепроверь по скриншоту — бот ошибается (перекрытие из-за собственного клика, подписи-глифы). Никите — только подтверждённое, цифрами: год, что видно, скриншот.
5. Отчёт в `work/playtest/` в git не идёт (`.gitignore`); подтверждённые находки — карточки F-NN в Notion.
