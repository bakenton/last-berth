Баланс — ботами, не на глаз (CLAUDE.md). Ботов под результат не подгонять.

1. **До.** Если эталон не свежий (HANDOFF: «красный — только эталон ботов»), сначала прогон без правок: `bash tools/regress.sh sim` и `node tools/sim-diff.js` — это точка отсчёта «до», а не `tools/sim-baseline.tsv`.
2. **Правка.** Одна величина за прогон (иначе не поймёшь, что сдвинуло). Запиши: что, было → стало, чьё решение (Никиты или провизорное).
3. **После.** `bash tools/regress.sh sim` (8 сидов, 4500 лет, ~3 мин; FAIL против эталона ожидаем) → `node tools/sim-diff.js`. Для разбора причин, а не цифр — агент `balance`; его отчёт перепроверь по логу.
4. **Критерии (F-20), по сидам:** idle и greedy — пол, обязаны проиграть (`sailed 0/8`); стили rush / serial / visitor / hoarder / ark / bank обязаны уходить на ковчеге хотя бы на половине сидов (≥4/8). Не доходит стиль — это вопрос к балансу игры, а не к боту.
5. **Ответ Никите — таблица**, не проза: бот · ушли на ковчеге до→после · год конца · ключевая колонка, которую ты трогал. Под ней одна строка вывода и рекомендация (оставить / откатить / другое значение с оценкой). Факты и догадки раздели.
6. **Эталон:** `--rebaseline` только по решению Никиты. Спроси одним вопросом с рекомендацией; без «да» не перезаписывай.
7. Записать в CHANGELOG и Журнал решений (Notion, «Кто решил») — как при закрытии итерации (`/close-iteration`).
