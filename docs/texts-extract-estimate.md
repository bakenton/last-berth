# Вынос текстов из страницы в отдельный файл — оценка (не делалось), 01.10.2026

**Сейчас:** 747 строк EN/RU в `<script type="application/json" id="lb-texts">` — 96 КБ из 462 КБ страницы (ядро 94, интерфейс 119, zip инструментов 110). `applyTexts()` в ui.js читает блок синхронно при старте.

**Что затронет**
| Где | Что меняется | Объём |
|---|---|---|
| build.py | писать `texts.json` вместо блока (или оба) | ~20 строк |
| texts-pull.js, sheet-merge.py | читать/писать `texts.json` вместо регэкспа по странице | ~15 + ~5 строк |
| ui.js | `fetch('texts.json')` → старт становится асинхронным; первый `draw()` ждёт тексты | ~30 строк, риск порядка инициализации |
| публикация | `files: {"texts.json": …}` рядом с index.html | одна строка, но см. риск 2 |
| pw12 | сравнение видимого текста до/после — главный тест такой правки | прогон |
| jp.ver | своя сборка со своими текстами | отдельно |

**Риски**
1. `file://` — Chromium не даёт `fetch` локального файла: сломаются `play/LAST-BERTH-*.html` (двойной клик) и все Playwright-сценарии. Нужен запасной вшитый блок → страница не худеет.
2. Опубликованные вспомогательные файлы артефакта уже расходились со страницей (tools/ застряли на v4.2). Тексты, разъехавшиеся с кодом, — плейсхолдеры `{n}` без значений прямо у игрока.
3. Кнопка «Подтянуть тексты» (вкладка Земля) уже подменяет блок на лету — второй источник текстов усложнит её.

**Выгода для кредитов — малая.** Тексты попадают в контекст, только если страницу открыть целиком; с MAP.md и правилом «grep + окна ±40» этого не происходит. Artifact read сохраняет файл на диск, в контекст его не кладёт.

**Предложение:** не выносить. Вместо этого `build.py` пишет рядом `work/texts.tsv` (таблица \t ключ \t en \t ru) только для чтения и grep — ~5 строк, без риска для игры. Трудозатраты полного выноса — около одной итерации (полдня сессий) плюс полный регресс и проверка jp.ver; оправдано, только если страница упрётся в лимит размера артефакта (16 МБ — далеко).
