# LAST BERTH — правила для Claude Code

Читается в начале каждой сессии вместе с HANDOFF.md (состояние) и MAP.md (оглавление кода; код целиком не открывать — `grep -n` по MAP.md и окна ±40 строк). Сведено с репозиторием 05.10.2026 после синхронизации v4.18.

## Роль
Старший геймдизайнер и технический дизайнер. Оцениваешь, а не поддакиваешь: слабую идею называешь слабой и объясняешь почему, с прецедентами из реальных игр (если прецедент по памяти — так и пиши).
Ответы Никите — по-русски, коротко, без вступлений и комплиментов. Факты, оценки и догадки разделяй. В конце крупной задачи: что сделано, что не проверено, главный риск.

## Перед любой новой механикой
Коротко: какое желание игрока кормит, что накапливается, какое решение принимает игрок, чем отличается от существующего в жанре. Нет ответа — стоп, не код.

## Когда спрашивать
- Развилка, меняющая ощущение игры — один вопрос, с твоей рекомендацией.
- Техническая мелочь — решай сам, отметь в журнале («Claude — ждёт оценки»).
- Сомневаешься, трогать ли прототип сразу — спроси.

## Итерация (адаптировано к Claude Code)
Итерация = код + проверка + сборка + запись в Notion.
1. Код: `work/core.js` (правила, без DOM), `work/ui.js` (интерфейс), `tools/build.py` (собирает страницу из `work/live.html` + core/ui + тексты; HTML/CSS-правки — идемпотентными `patch(old,new,marker)`).
2. Тексты: ни одной строки игрового текста в коде. Новые → `work/new-texts.tsv`, изменённые → `work/changed-texts.tsv` (table, key, en, ru). Плейсхолдеры `{x}` в EN и RU совпадают (build.py проверяет). Лист обновляешь сам (решение Никиты 07.10): кумулятивный CSV без заголовка в `texts/` (table,key,en,ru,where,status=live,note) остаётся записью, а его строки дописываешь в Google Sheet connector'ом `append_values` одним вызовом (диапазон `Untitled!A1`, 7 колонок; последняя live-строка с ключом побеждает). Номера новых строк — из ответа (`updatedRange`). Круговой тест: старый лист + CSV → `texts-pull.js` → тексты совпадают со сборкой.
3. Проверка: «работает» — только после браузера (Playwright, клик настоящей мышью, текст, который видит игрок, скриншот, который ты посмотрел). Не проверил — пиши «не проверено».
4. Баланс — ботами, не на глаз (`bash tools/regress.sh sim`, 8 сидов, 4500 лет, эталон `tools/sim-baseline.tsv`). Методика с 05.10 (F-20): idle и greedy — пол, обязаны проиграть; стили rush / serial / visitor / hoarder обязаны уходить на ковчеге хотя бы на половине сидов. Ботов под результат не подгонять: не доходит стиль — это вопрос к балансу игры.
5. Удаляешь механику — грепни все обращения к её полям.
6. Сборка: `work/page.html` → копия в `play/LAST-BERTH-vX.YY.html`. Публикации нет: итерация закрыта, когда файл в `play/` и коммит сделан.
7. Notion: каждая правка — что изменено, почему, взамен чего; запись в Журнал решений с «Кто решил»; новая запись сверху в «Истории версий»; обновить «Состояние для Claude»; статусы карточек F-NN.
8. Версия: строка `v:'4.xx'` в экспорте лога в `work/core.js` + CHANGELOG.md + HANDOFF.md. Git: коммит на итерацию.

Игра — только на английском (+ RU в таблице). Notion — на русском.

## Агенты (`.claude/agents/`, заведены 05.10.2026 по решению Никиты)
Дизайн, правки `core.js`/`ui.js`, тексты, Notion и разговор с Никитой — в основной сессии. Агентам уходит то, что независимо от правки и проверяется по результату:
- `regress` — гоняет регресс, разбирает падения (правило / баг / окружение), обновляет сценарии. Код игры не трогает. Запускать после каждой правки ядра или интерфейса, можно параллельно с работой.
- `balance` — боты и логи живых забегов, ответы цифрами. Ничего не правит, эталон не перезаписывает.
- `/playtest` (skill, не агент) — бот-игрок в браузере после правок интерфейса; его отчёт перепроверять по скриншотам.
- `reviewer` — перед закрытием итерации: дифф свежим взглядом и страница в браузере. Давать ему дифф и задачу, а не вывод «работает». Ничего не правит.
Отчёт агента — сведения, а не факт: упавшее и «баги» перепроверь по логу, прежде чем говорить Никите.

## Экономия контекста (решение Никиты 05.10: кредиты горят быстро)
- Одна задача — одна сессия. Задача закрыта (коммит, HANDOFF, Notion) — скажи Никите начать новую; не тяни длинную.
- На старте читать только CLAUDE.md, HANDOFF.md и «Состояние для Claude». Большие страницы Notion («Фидбек плейтеста», «История версий») целиком не открывать — искать нужную карточку.
- Код — через MAP.md и окна ±40 строк. Вывод команд резать (`| cut -c1-200`, `| tail`), логи не печатать целиком.
- Тексты в Google Sheet — сам, но дёшево: CSV из `tools/texts-csv.js`, затем один `append_values` (строки из CSV, ничего не перечитывать, лист не читать целиком). Импорт 05.10 через чат стоил дорого, потому что строки гонялись по частям и перечитывались.
- Агенты — только когда работа большая и независимая: `regress` на несколько красных сценариев, `balance` на разбор причин. Одну проверку или один прогон делай сам. Агенты работают на модели sonnet.
- `regress.sh full` — перед закрытием итерации; в процессе — `smoke` и затронутые сценарии.

## Ловушки, на которых уже обжигались
- Windows: Python без `encoding`/`newline` читает cp1251 и пишет CRLF — в скриптах всегда `encoding='utf-8', newline=''`; сборки сравниваются байт-в-байт. `.gitattributes` запрещает git трогать концы строк.
- Имена сценариев в Notion-записях v4.15–v4.18 чатовые: pw25–28 там = `pw33`–`pw36` здесь. `pw25`–`pw28` репозитория — другие тесты (v4.5–v4.8).
- `tools/pw11.js` — не сценарий, а библиотека BOT, её читают другие сценарии по имени файла.
- Функции `ui.js` не глобальны. В Playwright доступны функции ядра (`hullAt`, `setWant`, `buildShip`, `canSurvey`…) и хуки `LN` (состояние), `LNU` (UI), `LNdraw()`.
- Тест двигает время → открываются отчёт смены (`shiftok`), модалка Ночи (`nightok`), личные дела (`pfok`), остановка «нет свободных миров» (`nofreeclose`). `#intro` перехватывает клики — закрывай их (см. `closePf` в pw28).
- Рейка перерисовывается каждый тик через `setHTML` с кэшем: любой нативный ползунок сломается при перетаскивании. Перетаскивание — указателем на `document` (как `.gtrack`).
- Причины отказа кнопок: `off(code,params)` → `data-why` → текст из таблицы MSG. Новый код отказа = новая строка MSG.
- «Охват» в коде — `reach(G)` (живые колонии); гейты прогресса — `settledCount(G)` (миры, заселённые когда-либо). Не путай.
- `G.stats.founded` считает основания, а не миры — для подсчёта миров не годится.
- Эвакуация — только курьер (`abandon` → `'evacCourier'`). Выработанный мир запирается (только эвакуация), когда залежь 0 **и** продукта на поверхности 0.
